# Memory Management and Virtual Memory

## 1. What is Memory Management?

**Memory management** is the function of the operating system responsible for managing main memory (RAM) and allocating memory to processes.

The OS needs to:

```text
Allocate memory
Deallocate memory
Track memory usage
Protect processes
Manage virtual memory
```

---

# 2. Why is Memory Management Needed?

Multiple processes need memory at the same time.

```text
RAM
├── OS
├── Process P1
├── Process P2
└── Process P3
```

The OS must ensure that:

- Each process gets the required memory.
- Processes do not incorrectly access each other's memory.
- Memory is used efficiently.
- Processes can run even when RAM is limited.

---

# 3. Logical Address vs Physical Address

## Logical Address

A **logical address** (often called a virtual address) is the address generated by the CPU for a process.

## Physical Address

A **physical address** is the actual location in main memory (RAM).

```text
CPU
 ↓
Logical / Virtual Address
 ↓
MMU
 ↓
Physical Address
 ↓
RAM
```

---

# 4. What is the MMU?

**MMU (Memory Management Unit)** is hardware responsible for translating virtual/logical addresses into physical addresses.

```text
CPU
 ↓
Virtual Address
 ↓
MMU
 ↓
Physical Address
 ↓
RAM
```

### Interview Answer

> The MMU is hardware that translates virtual addresses generated by the CPU into physical memory addresses.

---

# 5. Contiguous Memory Allocation

In **contiguous memory allocation**, a process is allocated one continuous block of physical memory.

Example:

```text
RAM

| OS | Process 1 | Process 2 | Free Space |
```

The process occupies consecutive memory locations.

---

# 6. Fragmentation

Fragmentation occurs when available memory is not used efficiently.

There are two important types:

```text
Internal Fragmentation
External Fragmentation
```

---

# 7. Internal Fragmentation

**Internal fragmentation** occurs when allocated memory contains unused space inside the allocated block.

Example:

```text
Requested: 18 KB
Allocated: 20 KB

Unused:
2 KB
```

```text
| Process Data | Unused |
```

The unused space is inside the allocated region.

---

# 8. External Fragmentation

**External fragmentation** occurs when enough total free memory exists, but it is divided into separate small holes.

Example:

```text
| P1 | Free | P2 | Free | P3 | Free |
```

Suppose:

```text
Free = 10 KB + 10 KB + 10 KB
Total Free = 30 KB
```

A process requiring one contiguous block of:

```text
25 KB
```

may still not fit.

---

# 9. Internal vs External Fragmentation

| Internal Fragmentation | External Fragmentation |
|---|---|
| Unused space inside allocated blocks | Free space scattered outside allocated blocks |
| Memory is allocated but partly unused | Total free memory may be sufficient but fragmented |
| Common with fixed-size allocation | Common with variable-size contiguous allocation |

### Easy Memory Trick

```text
Internal
→ Inside allocated block

External
→ Outside allocated blocks
```

---

# 10. What is Paging?

**Paging** is a memory-management technique that divides:

```text
Logical/Virtual Memory → Pages
Physical Memory → Frames
```

Pages and frames have the same fixed size.

Example:

```text
Virtual Memory

| Page 0 | Page 1 | Page 2 | Page 3 |
```

```text
Physical Memory

| Frame 0 | Frame 1 | Frame 2 | Frame 3 | ...
```

A page can be placed into any available physical frame.

---

# 11. Page

A **page** is a fixed-size block of virtual/logical memory.

```text
Virtual Memory
├── Page 0
├── Page 1
├── Page 2
└── Page 3
```

---

# 12. Frame

A **frame** is a fixed-size block of physical memory.

```text
Physical Memory
├── Frame 0
├── Frame 1
├── Frame 2
└── Frame 3
```

The page size and frame size are equal.

---

# 13. Page Table

A **page table** stores the mapping between virtual pages and physical frames.

Example:

```text
Page        Frame

Page 0  →   Frame 3
Page 1  →   Frame 1
Page 2  →   Frame 7
Page 3  →   Frame 4
```

---

# 14. Address Translation in Paging

A virtual address is divided into:

```text
Page Number
Offset
```

The page number is used to find the corresponding frame in the page table.

```text
Virtual Address
┌──────────────┬────────┐
│ Page Number  │ Offset │
└──────────────┴────────┘
       ↓
   Page Table
       ↓
    Frame Number
       ↓
Physical Address
┌───────────────┬────────┐
│ Frame Number  │ Offset │
└───────────────┴────────┘
```

The offset remains unchanged.

---

# 15. Why is Paging Useful?

Paging provides:

```text
No requirement for contiguous physical allocation
Better memory utilization
Support for virtual memory
Reduced external fragmentation
```

Paging can still have **internal fragmentation**, typically in the last page of an allocation.

---

# 16. What is Segmentation?

**Segmentation** divides a program's logical address space into variable-sized logical segments.

Examples:

```text
Code
Data
Stack
Heap
```

Each segment can have a different size.

```text
Program
├── Code Segment
├── Data Segment
├── Stack Segment
└── Heap Segment
```

---

# 17. Paging vs Segmentation

| Paging | Segmentation |
|---|---|
| Fixed-size blocks | Variable-size blocks |
| Divides memory into pages/frames | Divides program into logical segments |
| Mainly physical/memory-management oriented | Represents logical program structure |
| No external fragmentation from page allocation | Can suffer from external fragmentation |

---

# 18. What is Virtual Memory?

**Virtual memory** is a memory-management technique that allows a process to use an address space larger than the amount of physical RAM currently available.

It allows the OS to keep only the necessary portions of a process in RAM while other portions can remain in secondary storage.

```text
Virtual Memory
      ↓
   Larger Address Space
      ↓
RAM + Secondary Storage
```

---

# 19. Why is Virtual Memory Needed?

Suppose:

```text
RAM = 8 GB
```

but a process has a virtual address space larger than the currently available physical memory.

Virtual memory allows the OS to keep only the actively needed portions in RAM.

```text
Process
├── Part in RAM
└── Part on Disk
```

When another part is needed, the OS can bring it into RAM.

---

# 20. Demand Paging

**Demand paging** loads a page into physical memory only when it is needed.

```text
Process requests Page 5
        ↓
Is Page 5 in RAM?
      /      \
    Yes       No
     ↓         ↓
 Continue   Page Fault
```

This avoids loading every page of a process into RAM before execution.

---

# 21. What is a Page Fault?

A **page fault** occurs when a process accesses a virtual page that is not currently present in physical memory.

Example:

```text
CPU requests Page 5
        ↓
Page 5 not in RAM
        ↓
Page Fault
        ↓
OS locates page on storage
        ↓
Loads page into RAM
        ↓
Updates page table
        ↓
Restarts/resumes instruction
```

A page fault is therefore **not necessarily an error**; it is a normal event in systems using demand paging.

---

# 22. Page Fault Handling

When a page fault occurs:

```text
1. CPU generates memory access.

2. Page is found to be not present.

3. Hardware traps into the OS.

4. OS checks whether the memory reference is valid.

5. OS locates the required page on secondary storage.

6. OS finds a free frame or selects a victim page.

7. Required page is loaded into RAM.

8. Page table is updated.

9. The interrupted instruction is restarted/resumed.
```

---

# 23. What is Page Replacement?

If there is no free frame when a required page must be loaded, the OS must select an existing page to remove from RAM.

This is called **page replacement**.

```text
RAM full
   ↓
Page replacement
   ↓
Choose victim page
   ↓
Load required page
```

---

# 24. FIFO Page Replacement

**FIFO (First-In, First-Out)** replaces the page that has been in memory the longest.

Example:

```text
Oldest → Replace first
```

### Advantage

```text
Simple
Easy to implement
```

### Disadvantage

It may remove a frequently used page just because it is old.

---

# 25. LRU Page Replacement

**LRU (Least Recently Used)** replaces the page that has not been used for the longest time.

Example:

```text
Pages:

A → used recently
B → used recently
C → not used for a long time

Replace C
```

The idea is:

> Pages used recently are likely to be used again soon.

---

# 26. Optimal Page Replacement

The **Optimal Page Replacement** algorithm replaces the page that will not be used for the longest time in the future.

It provides the minimum possible number of page faults for a given reference string.

However:

```text
Future references are unknown
```

Therefore, it cannot generally be implemented exactly in a real system.

It is mainly used as a theoretical benchmark.

---

# 27. FIFO vs LRU vs Optimal

| Algorithm | Replacement Rule |
|---|---|
| FIFO | Oldest page |
| LRU | Least recently used page |
| Optimal | Page used farthest in the future |

### Interview Priority

```text
FIFO ⭐⭐⭐
LRU ⭐⭐⭐⭐⭐
Optimal ⭐⭐⭐⭐
```

---

# 28. What is Belady's Anomaly?

**Belady's anomaly** is the situation where increasing the number of available page frames can sometimes increase the number of page faults.

It can occur with **FIFO** page replacement.

Example conceptually:

```text
More Frames
    ↓
More Page Faults
```

This surprising behavior is called Belady's anomaly.

---

# 29. Does LRU Suffer from Belady's Anomaly?

No.

LRU belongs to the class of **stack algorithms**, which have the property that increasing the number of frames does not increase the number of page faults for the same reference string.

---

# 30. What is Thrashing?

**Thrashing** occurs when the system spends most of its time handling page faults and moving pages between RAM and secondary storage instead of performing useful computation.

Example:

```text
Page Fault
   ↓
Load Page
   ↓
Another Page Fault
   ↓
Load Page
   ↓
Another Page Fault
   ↓
...
```

Result:

```text
Very high paging activity
↓
Poor CPU utilization / performance
```

---

# 31. Why Does Thrashing Occur?

A common cause is:

```text
Too many active processes
        ↓
Insufficient frames for their working sets
        ↓
Frequent page faults
        ↓
Thrashing
```

---

# 32. How Can Thrashing Be Reduced?

Possible approaches include:

```text
Reduce degree of multiprogramming
Allocate more frames to affected processes
Use working-set based techniques
Use page-fault frequency control
```

---

# 33. What is a TLB?

**TLB (Translation Lookaside Buffer)** is a small, fast cache that stores recent virtual-page-to-physical-frame translations.

Without TLB:

```text
CPU
 ↓
Page Table
 ↓
RAM
```

With TLB:

```text
CPU
 ↓
TLB
 ↓
Physical Address
 ↓
RAM
```

The TLB reduces the average cost of address translation.

---

# 34. What is a TLB Hit?

A **TLB hit** occurs when the required page-to-frame translation is found in the TLB.

```text
Virtual Page
     ↓
    TLB
     ↓
Translation Found
     ↓
Physical Frame
```

This avoids an additional page-table lookup in the common fast path.

---

# 35. What is a TLB Miss?

A **TLB miss** occurs when the required translation is not found in the TLB.

The system then needs to obtain the translation from the page table.

```text
Virtual Page
     ↓
    TLB
     ↓
   Miss
     ↓
Page Table
     ↓
Translation
```

A TLB miss is different from a page fault.

---

# 36. TLB Miss vs Page Fault

| TLB Miss | Page Fault |
|---|---|
| Translation not found in TLB | Required page not currently in RAM |
| Page may still be in RAM | Page must generally be brought into RAM |
| Usually much cheaper | Much more expensive |
| May require page-table lookup | Requires OS page-fault handling |

This distinction is frequently asked.

---

# 37. Page Fault vs TLB Miss

### TLB Miss

```text
Page may be in RAM
↓
Translation missing from TLB
↓
Look in page table
```

### Page Fault

```text
Page not in RAM
↓
OS handles fault
↓
Page brought into RAM
```

---

# 38. What is Swapping?

**Swapping** is a memory-management technique in which processes or memory contents are moved between RAM and secondary storage to manage limited physical memory.

Historically, entire processes could be swapped, while modern virtual-memory systems more commonly move pages or other memory units.

```text
RAM
 ↕
Secondary Storage
```

---

# 39. Paging vs Swapping

| Paging | Swapping |
|---|---|
| Works with fixed-size pages | Traditionally moves larger units such as entire processes |
| Fine-grained memory management | Coarser-grained |
| Commonly used in virtual memory | Historical/OS-dependent technique |
| Page faults bring needed pages into RAM | Swapping moves memory/process contents between RAM and storage |

---

# 40. What is a Working Set?

A process's **working set** is the set of pages it is actively using during a particular period.

Example:

```text
Process P1

Currently active pages:
P2
P4
P7
P8
```

These pages form part of its working set.

The concept is important for understanding and controlling thrashing.

---

# 41. What is Demand Paging vs Pre-Paging?

### Demand Paging

Load a page only when it is actually referenced.

```text
Reference page
      ↓
Page not in RAM
      ↓
Page Fault
      ↓
Load page
```

### Pre-Paging

Load pages in advance based on an expectation that they will soon be needed.

```text
Predict future access
       ↓
Load pages early
```

Pre-paging can reduce page faults when predictions are accurate, but unnecessary pages waste memory and I/O bandwidth.

---

# 42. What is Page Size?

**Page size** is the fixed size of a page in a paging system.

If:

```text
Virtual address size = 32 bits
Page size = 4 KB
```

Then:

```text
4 KB = 2¹² bytes
```

Therefore:

```text
Offset = 12 bits
```

Remaining:

```text
32 - 12 = 20 bits
```

are used for the page number.

---

# 43. Page Number and Offset

For a virtual address:

```text
┌───────────────┬──────────────┐
│ Page Number   │ Offset       │
└───────────────┴──────────────┘
```

If:

```text
Address size = N bits
Page size = 2^k bytes
```

Then:

```text
Offset bits = k
Page number bits = N - k
```

---

# 44. Important Numerical Concept

Suppose:

```text
Virtual address = 16 bits
Page size = 1 KB
```

Since:

```text
1 KB = 2¹⁰ bytes
```

Offset:

```text
10 bits
```

Page number:

```text
16 - 10 = 6 bits
```

Number of virtual pages:

```text
2⁶ = 64 pages
```
